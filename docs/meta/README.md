# BHE Meta

## Pourquoi ce dossier existe

Le développement de Boost Hyper Engine (BHE) produit continuellement :

- idées ;
- émergences architecturales ;
- arbitrages ;
- tensions ;
- méthodes de travail ;
- décisions différées ;
- intuitions encore floues.

Certaines de ces réflexions ne relèvent ni directement :

- de l’architecture du moteur ;
- ni des rapports techniques d’implémentation.

Ce dossier sert donc à documenter :

> la manière dont le projet pense, évolue et se construit.

Il constitue progressivement une mémoire réflexive du projet.

---

## Objectifs

Le dossier `meta/` vise à :

- préserver les raisonnements importants ;
- conserver les décisions différées ;
- éviter les redécouvertes inutiles ;
- expliciter les méthodes de travail ;
- documenter les tensions architecturales ;
- accompagner la montée en complexité du projet.

L’objectif n’est pas de figer BHE,
mais de lui permettre d’évoluer sans perdre sa continuité cognitive.

---

## Philosophie

Le système reste volontairement léger et émergent.

Aucune structure définitive n’est imposée à ce stade.

Le dossier évoluera progressivement selon les besoins réels du projet.

Principes actuels :

- architecture > vitesse ;
- greffes contrôlées ;
- helpers mérités ;
- pas d’abstractions spéculatives ;
- préserver autant les raisonnements que le code.

---

## Structure actuelle

### `methodology/`
Comment BHE est construit.

Exemples :
- workflow GPT / Codex / humain ;
- principes de développement ;
- méthodes de travail.

### `memory/`
Ce que le projet ne doit pas oublier.

Exemples :
- système anti-oubli ;
- décisions différées ;
- tensions architecturales ;
- signaux faibles ;
- branches futures possibles.

---

## Important

Une idée non priorisée n’est pas une idée rejetée.

Le projet cherche à préserver non seulement son code,

mais également :

- ses raisonnements ;
- ses tensions ;
- ses possibilités ;
- ses futurs potentiels.
