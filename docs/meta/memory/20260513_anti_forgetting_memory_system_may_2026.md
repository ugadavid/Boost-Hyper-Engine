# Anti-Forgetting Memory System
## Mai 2026 — Préserver les idées non priorisées dans le développement de BHE

---

# Contexte

Au cours des premières semaines de développement de Boost Hyper Engine (BHE), une difficulté importante apparaît progressivement.

Le projet génère continuellement :
- idées ;
- variantes ;
- intuitions ;
- pistes architecturales ;
- expérimentations potentielles ;
- améliorations futures.

Cependant, le travail réel impose régulièrement :
- de prioriser ;
- de trancher ;
- de choisir une direction ;
- de limiter les explorations.

Conséquence :

certaines idées importantes disparaissent progressivement,
non parce qu’elles sont mauvaises,
mais simplement parce qu’elles ne sont pas immédiatement retenues.

---

# Le problème identifié

Une idée non retenue immédiatement n’est pas forcément :
- invalide ;
- abandonnée ;
- inutile.

Elle peut être :
- trop précoce ;
- trop coûteuse à court terme ;
- dépendante d’une autre évolution ;
- ou simplement hors du focus actuel.

Pourtant, sans système de conservation explicite :
- ces idées se perdent ;
- les arbitrages disparaissent ;
- les discussions doivent être recommencées ;
- certaines intuitions sont redécouvertes plusieurs fois.

Le projet identifie alors un nouveau besoin méthodologique :

> construire une mémoire des possibilités non immédiatement priorisées.

---

# Changement de perspective

Le système adopte progressivement une idée importante :

> une idée non priorisée n’est pas une idée rejetée.

Cette distinction devient fondamentale.

Le but n’est plus uniquement :
- de décider ;
- ou d’avancer ;

mais également :
- de préserver les branches possibles du projet.

---

# Objectifs du système

Le système “anti-oubli” vise progressivement à :

- conserver les idées importantes ;
- réduire la charge mentale ;
- éviter les redécouvertes inutiles ;
- préserver les intuitions émergentes ;
- historiser les arbitrages ;
- maintenir les futurs possibles du projet.

Mais aussi :

- permettre au cerveau de lâcher prise ;
- faciliter la priorisation ;
- éviter la peur de “perdre une idée”.

---

# Nature des éléments conservés

Le système ne vise pas uniquement des tâches techniques.

Il doit pouvoir accueillir :

## Idées architecturales
Exemples :
- nouvelles abstractions ;
- futurs modules ;
- concepts transversaux ;
- stratégies adaptatives.

## Intuitions pédagogiques
Exemples :
- nouvelles interactions ;
- variations multimodales ;
- nouvelles formes d’adaptation ;
- scénarios d’usage.

## Tensions détectées
Exemples :
- zones de couplage ;
- limites du modèle actuel ;
- compromis temporaires ;
- dette conceptuelle.

## Pistes techniques
Exemples :
- refactorisations possibles ;
- idées de structure ;
- optimisations futures ;
- outils à explorer.

## Idées “faibles”
Le système accepte également :
- intuitions vagues ;
- idées incomplètes ;
- formulations non stabilisées.

Certaines idées importantes apparaissent d’abord sous forme très floue.

---

# Différence avec une simple TODO list

Le système ne doit pas devenir :
- une liste de tâches ;
- un backlog produit classique ;
- une accumulation de tickets.

Le but principal est :

> préserver le potentiel cognitif du projet.

La mémoire doit pouvoir contenir :
- du possible ;
- du flou ;
- des pistes ;
- des signaux faibles ;
- des embranchements.

---

# Catégories envisagées

Plusieurs catégories commencent progressivement à émerger.

## 1. Future Ideas

Idées intéressantes mais hors focus actuel.

Exemples :
- analytics avancés ;
- objets composites ;
- moteur narratif ;
- export pédagogique.

---

## 2. Architectural Signals

Points qui semblent révéler :
- une future abstraction ;
- une faiblesse du modèle ;
- un invariant émergent.

Exemples :
- montée en abstraction de InteractionData ;
- multimodalité ;
- renderer générique.

---

## 3. Deferred Decisions

Décisions volontairement reportées.

Exemples :
- structure finale du moteur ;
- séparation packages ;
- stratégie plugin ;
- architecture auteur.

---

## 4. Experimental Branches

Pistes exploratoires non stabilisées.

Exemples :
- moteur vocal ;
- objets narratifs ;
- adaptation IA ;
- structures immersives.

---

# Intégration au workflow GPT / Codex / Humain

Le système anti-oubli devient progressivement une extension naturelle du workflow hybride.

## GPT
Peut aider à :
- détecter les idées émergentes ;
- identifier les signaux faibles ;
- reformuler les intuitions ;
- transformer des discussions en mémoire exploitable.

## Codex
Peut contribuer à :
- maintenir la structure documentaire ;
- déplacer les idées ;
- consolider certains fichiers ;
- générer des rapports techniques associés.

## Humain
Reste responsable :
- des arbitrages ;
- des priorités ;
- de l’importance accordée aux pistes ;
- de la validation des futures directions.

---

# Effet psychologique important

Le système produit progressivement un effet important sur le travail lui-même.

Lorsque les idées sont conservées explicitement :
- le cerveau relâche une partie de sa tension ;
- la peur de perdre diminue ;
- la priorisation devient plus facile ;
- les arbitrages deviennent moins douloureux.

Le projet gagne alors :
- en stabilité ;
- en continuité ;
- en sérénité cognitive.

---

# Formes possibles du système

Le système pourra progressivement prendre plusieurs formes :

- backlog d’idées ;
- documents de signaux faibles ;
- ADR différés ;
- timelines ;
- notes de tensions architecturales ;
- “parking” d’idées futures ;
- cartes conceptuelles.

Aucune structure définitive n’est encore imposée.

Le système lui-même doit rester :
- léger ;
- flexible ;
- évolutif.

---

# Principe fondamental

Le système repose progressivement sur une idée simple :

> le projet doit préserver davantage que son code.

BHE doit également conserver :
- ses raisonnements ;
- ses tensions ;
- ses possibilités ;
- ses futurs potentiels.

---

# État du système à ce stade

À ce stade du projet :

le système anti-oubli reste encore embryonnaire,
mais son besoin devient déjà clairement visible.

Le projet commence progressivement à comprendre que :

> la mémoire architecturale d’un système ne se limite pas aux décisions prises,
> mais inclut également les chemins momentanément laissés de côté.
